# VIORA Android 1.0.2 — проверка восстановления соединения

Проверка исходного сбоя на затронутом телефоне: пользователь подтвердил работу
браузера и Telegram через XHTTP TLS. Это не является заявлением о полной
проверке всех режимов VPN и всех сетей.

## Изменения

- Физические сети Android отслеживаются по снимкам, переданным в callback.
  Сокеты используют `VpnService.protect` и системную сеть по умолчанию;
  VPN больше не объявляет явную привязку, которой у сокетов фактически нет.
- После обновления параметров активной подписки соединение последовательно
  останавливается и запускается с новой конфигурацией. Повторное обновление
  во время этого переключения отклоняется.
- Если полная ссылка выбранного сервера изменилась, соответствие ищется только
  в обновляемой подписке: уникальный адрес/порт с прежним транспортом и защитой,
  затем уникальное название с ними, затем единственный совместимый транспорт.
  Поэтому обновление UUID или порядка параметров не сбрасывает XHTTP на WS.
  Точное прежнее совпадение имеет приоритет; неоднозначность использует прежний
  резервный вариант первого входящего профиля. Другие подписки не перехватывают
  текущий выбор.
- Новый запуск из плитки или от Android отделён от запоздалого события
  предыдущей неудачной попытки.
- Проверка пинга отдельно показывает TCP-доступность порта и результат HTTPS
  через активный Xray. URL передаётся в VPN-процесс явно; ответы сопоставляются
  с запросами, приёмник регистрируется до отправки и снимается после таймаута.
- Ошибка подготовки плитки больше не исчезает при обычном сохранении настроек.

## Воспроизводимые проверки

Из `apps/client`:

```text
flutter test --no-pub --reporter expanded
flutter analyze --no-pub
```

Результат: 171 тест пройден, 5 пропущены по платформенным условиям;
статический анализ без замечаний. Проверки включают задержанную остановку,
конкурирующее обновление подписки, события после таймаута, запуск из плитки,
отказы и устаревшие ответы проверки соединения, сохранение XHTTP при ротации
UUID/параметров/названия и изоляцию выбора между подписками.

Нативные host-проверки: 10 сценариев выбора физической сети, 19 сценариев
валидации URL и 9 сценариев происхождения/повторения команд запуска. Эти
проверки не являются испытанием реального туннеля.

Пользователь подтвердил работу сайта и Telegram на промежуточной сборке
1.0.2 (30) с сетевыми исправлениями, установленной поверх 1.0.1. Окончательная
сборка (32) дополнительно защищает обновление подписки и выбор сервера; она
установлена поверх прежней. Android подтвердил versionName 1.0.2, versionCode
32. После холодного запуска XHTTP TLS сохранился. Повторное подключение и
HTTPS-проверка успешны: TCP 97 мс, HTTPS
через активный движок 72 мс. Это измерение отклика одного запроса, не скорости
канала. Браузер и Telegram автоматически не открывались. SHA-256 APK:

```text
6d9c7fcdaf1070ca0d7be0ee686718db134de8722afde86e6e8d0aa0407b07e0
```

## Ограничения

Успешный HTTPS-запрос через активный движок обходит вход TUN и не доказывает
работоспособность каждого приложения, отсутствие DNS/IP-утечек или скорость
VPN. Единственная первопричина исходного сбоя не установлена. Мобильная сеть,
перезагрузка и длительная работа именно на новой сборке не проверены.
При переходе в администрирование ожидающее отложенное согласование подписки
привязано к жизненному циклу клиентской страницы; при таком редком пересечении
может потребоваться ручное переподключение.

TLS-проверка сохранена. Данные приложения и HWID не сбрасывались. VPN и
сетевые настройки компьютера не изменялись. Windows/Linux этим кандидатом
не обновляются.
