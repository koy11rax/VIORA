# VIORA Linux 1.0.0

Пакеты для Linux x86_64 используют один заново собранный клиент GTK 3:

- Debian/Ubuntu: `sudo apt install ./Viora-Linux-1.0.0-amd64.deb`.
- Fedora: `sudo dnf install ./Viora-Linux-1.0.0-1.x86_64.rpm`.
- Arch: `sudo pacman -U ./viora-bin-1.0.0-1-x86_64.pkg.tar.zst`.

Для установки потребуется пароль администратора. Сам интерфейс работает от обычного пользователя; системное разрешение polkit требуется отдельному VPN-компоненту. Установка пакета сама VPN и постоянную блокировку не включает.

Требуются glibc 2.35+, GTK 3, Secret Service, polkit, nftables и systemd-resolved. Для ранней защиты поддержаны systemd с NetworkManager или systemd-networkd. В GNOME может понадобиться расширение индикаторов. Fedora Atomic/Flatpak, OpenRC, ARM и старые дистрибутивы в этот набор пакетов не входят. Формат RPM или Arch-пакета сам по себе не доказывает совместимость с каждой версией дистрибутива.

Запусти VIORA из меню приложений или командой `viora`. Для сохранения аккаунта и серверов разблокируй системную связку ключей. Импортируй подписку из бота, затем выбери сервер. Для режима «Только выбранные приложения» сначала укажи нужные исполняемые файлы. Для Flatpak, оболочек и программ с несколькими процессами может потребоваться выбор фактического исполняемого файла.

## Постоянная защита

Сначала импортируй подписку и сохрани сервер. Отключи VPN, открой «Настройки → Соединение и защита → Постоянная блокировка без VPN» и подтверди включение. Состояние показывается только после ответа системного компонента. Затем подключи VPN на главной странице.

При включённой блокировке интернет без VPN недоступен после ручного отключения, закрытия VIORA и перезагрузки. Прямые правила, российские сервисы, локальная сеть и исключённые приложения тоже блокируются. Автоматический запуск самого VPN при загрузке Linux этим не добавляется: автоподключение применяется при открытии VIORA. Подписки и управление аккаунтом без работающего VPN могут быть недоступны.

Чтобы вернуть обычный интернет, отключи VPN, дождись остановки и нажми «Выключить защиту». Если интерфейс недоступен:

```sh
sudo /usr/lib/viora/viora_tunnel --protection recover
```

Если компонент уже удалён вручную, восстановление только правил VIORA:

```sh
sudo nft delete table inet viora_lockdown
sudo rm -f /var/lib/viora/protection.enabled
sudo systemctl daemon-reload
```

Команда nft может сообщить, что таблица уже отсутствует. Не сбрасывай остальные правила firewall. Штатное полное удаление пакета снимает правила VIORA; обновление сохраняет выбранную блокировку. Установка не перезапускает сетевые службы. Если ранее включённая защита не загрузится до сети, зависимости NetworkManager/systemd-networkd могут остановить их запуск до восстановления.

## Проверка загрузки и подписи

Рядом с каждым пакетом находится файл SHA-256. Выполняй проверку из папки с обоими файлами, например:

```sh
sha256sum -c Viora-Linux-1.0.0-amd64.deb.sha256
```

Контрольная сумма проверяет целостность, а не удостоверяет издателя. Пакеты не подписаны доверенным ключом издателя. Не отключай общую проверку подписей системы. Исходники клиента и закреплённого движка поставляются отдельно в `Viora-Desktop-1.0.0-source.zip`.

Содержимое и метаданные пакетов проверяются без их установки на пользовательскую систему. Проверки кода и сборка не являются подтверждением отсутствия сетевых утечек. Реальные подключения VPN, работа firewall при обрывах, загрузка ОС с включённой политикой, Fedora и Arch как установленные целевые системы требуют отдельной приёмки.
