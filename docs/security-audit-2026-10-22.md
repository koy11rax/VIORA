## 4. Интерфейс

В рабочий Flutter-клиент перенесён стиль последнего согласованного React-макета: графитовые поверхности, фирменный настоящий V, мягкое выделение навигации, панель соединения с круговой кнопкой, счётчики, серверы и маршруты рядом, подписка ниже. Android использует четыре нижних раздела; маршрутизация доступна из настроек, администрация — только для подтверждённого владельца через верхнюю кнопку.

Анимация реагирует на настоящую фазу контроллера, отключение и уменьшение движения. Занятые действия отключаются, ошибки остаются видимыми. Значения времени/трафика берутся из native events. Ни новая кнопка, ни анимация не создаёт фиктивного соединения. Короткое «Туннель запущен» не является результатом проверки публичного IP. Функции, существующие лишь в интерактивном React-макете, не объявляются автоматически реализованными в native-приложении.

UI-тесты и снимки 1280/390/360 проверены вручную. Это настоящие Flutter-виджеты с изолированным native fixture, не работающий реальный туннель. Полная сертификация доступности и длительные измерения кадров не выполнялись.

## 7. Зависимости и происхождение

Создан inventory 101 уникальной Go/Pub координаты; OSV querybatch вернул ошибку HTTP. Дополнительно установлен только в audit-каталог официальный govulncheck v1.9.0 с проверенным tag/commit; реально запущены desktop symbol scan и Android package scan. Оба остановились на HTTP 403 от базы vuln.go.dev. Поэтому результат всего Go/Pub графа **неизвестен**, не «чисто», и достижимость CVE не утверждается. Python pip-audit проверил только отдельно установленное тестовое окружение: известных advisory не сообщил. Это не скан рабочего сервера: его фактические версии и конфигурация отсутствуют. Полного production Python lock нет; requirements-test.txt явно ограничен HTTP-тестами. Прочитаны закреплённые Gradle/Kotlin/AndroidX версии; после сборки отдельно сохранено debugRuntimeClasspath дерево Android. Полной advisory-проверкой Maven это не является.

Проверены существующие pins Android core/Wintun/Xray и source packaging whitelist. Восстановление недостающего Go cache выполнялось по закреплённым версиям с проверкой go.sum; транспортные версии не обновлялись. Не было массового обновления библиотек. Добавленные tool checksums не меняют upstream Xray. Бинарные хеши обеспечивают целостность, но не заменяют подпись доверенного издателя. При сборке APK официальный Google storage вернул 403; использованы существующий локальный Gradle-профиль Google Maven и процессный FLUTTER_STORAGE_BASE_URL для CFUG-зеркала из документации Flutter. Глобальные настройки не менялись. [Документация Flutter](https://docs.flutter.dev/community/china) прямо указывает, что команда Flutter не гарантирует безопасность/надёжность зеркал; это отдельная граница доверия, не доказательство идентичности артефактов официальному хосту.

Методика Go vulnerability management: https://go.dev/doc/security/vuln/ . Логи неуспешного advisory lookup: govulncheck-desktop.err, govulncheck-android-module.err. Официальный источник checksum Gradle: https://services.gradle.org/distributions/gradle-8.12-all.zip.sha256 .

## 8. Не проверено и оставшиеся риски

- Реальная смена публичного IP, передача данных, DNS/IPv6/WebRTC leaks, kill switch при crash/reboot, длительная сессия, смена сетевых интерфейсов и взаимодействие с другим VPN. Изменять рабочую сеть для имитации доказательства не стали. Нужна выделенная среда и тестовый сервер, не production подписка владельца.
- Native CONNECTED подтверждает локальный core/TUN, не удалённый handshake. UI не обещает доказанную доступность интернета; отдельная end-to-end проверка требует согласованной политики endpoint/приватности.
- Windows broker разрешает интерактивным пользователям управлять общей защитой вне активной сессии. На многопользовательском ПК нужно отдельное решение о владельце политики; права молча не ужесточались.
- Linux validator намеренно отклоняет неизвестные JSON-формы nft. Проверены схемы и фикстуры; нужна интеграция на поддерживаемых Ubuntu/Fedora/Arch, чтобы исключить ложный отказ статуса.
- Проверка Windows block filters не доказывает корректность всех permit exceptions и влияние сторонних WFP providers. Нужен отдельный VM/boot/leak тест.
- Незавершённая admin-выдача оставляет durable reservation. Перед повтором оператор должен сверить реальные внешние эффекты; автоматическое снятие по таймауту было бы небезопасным.
- В фото-предпросмотре поддержки остаются блокирующие PIL/SQLite операции в event loop. Это MEDIUM риск отзывчивости, не подтверждённая компрометация. Реальный production callback выдачи/оплаты и deployment не проверены.
- Race detector, широкая проверка screen reader/масштабов, чистая установка/удаление и новые Linux UI пакеты не проверены. Запуск Windows EXE с настройками владельца может включить автоподключение; вместо этого использованы изолированные widget/IPC проверки.
- Android build сохраняет предупреждения о Java source/target 8, старом XML parser SDK, namespace в upstream manifest, flatDir и deprecated Gradle API. Они не скрывались и не устранялись массовым обновлением toolchain. Android Release/R8 остаётся непроверенным; Debug APK не является обновлением стабильного подписанного приложения и не рекомендуется для замены установки владельца.
- У release Windows/Linux нет нового сертификата издателя. Подпись не покупалась, существующие ключи не читались и не заменялись. Старые дистрибутивы не становятся проверенными от изменения исходников.

## 10. Итог и восстановление

Подтверждённые исправления внесены в существующий проект и проверены доступными автоматическими средствами. Полная безопасность и готовность нового публичного VPN-релиза не заявляются: сетевые/OS испытания и некоторые платформенные сборки остаются отдельными воротами выпуска.

Для сравнения/отката есть исходный архив с SHA-256 и diff. Автоматически не откатывайте весь проект поверх чужих последующих правок. Рабочий бот ещё использует прежний установленный код: исходное исправление сервера само по себе не развёртывается удалённо. Готовый набор изменений можно переносить только после обычной проверки deployment/приёмки; существующие пользовательские данные не удалялись.
