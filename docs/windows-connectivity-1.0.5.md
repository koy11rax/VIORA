# Windows 1.0.5: новый модуль подключения

В Windows заменён слой TUN. Служба запускает два проверенных компонента:
sing-box 1.14.4 создаёт системный TUN Windows, Xray обслуживает только локальный
SOCKS и существующий VLESS-транспорт. Прежний Xray TUN на Windows не запускается.
Linux сохраняет прежнюю реализацию. Android не пересобирался и не обновлялся.

## Совместимость

Интерфейс и формат настроек сохранены. Ссылки подписки, аккаунт, существующий
HWID, выбранный сервер, MTU и режим приложений не сбрасываются. Поддерживаются
прежние WS TLS, XHTTP TLS и REALITY Vision. Порядок доменных правил, подсетей,
портов и исключений приложений переносится в sing-box. Windows-пути приложений
сопоставляются целиком без учёта регистра. IPv6 перехватывается и блокируется.
DNS обрабатывается внутри VPN; обычный режим использует HTTPS. Обратное
сопоставление общего IP CDN домену отключено, чтобы неизвестный трафик не
наследовал чужое правило прямого доступа.

При постоянной защите прямые исключения остаются заблокированными. Политика
WFP не снимается при ошибке подключения или закрытии приложения.

## Жизненный цикл и границы привилегий

- Защищённая служба проверяет хеши обоих движков и подписанный Wintun перед
  запуском. Исполняемые файлы остаются в фиксированном Program Files.
- Конфигурации передаются через stdin в памяти; секреты не передаются в
  аргументах, временных файлах и диагностических отчётах.
- Локальный SOCKS слушает только 127.0.0.1 с новыми случайными учётными данными
  для каждой сессии. Перед запуском TUN проверяются PID владельца порта и
  аутентификация. Проверка готовности не делает запрос к удалённому серверу.
- Xray привязывается к выбранному до TUN сетевому интерфейсу для предотвращения
  возврата собственного транспортного соединения в туннель. Потеря интерфейса
  завершает сессию; клиент использует ограниченные попытки переподключения.
- Supervisor запускает backend, ждёт его готовности, затем запускает frontend.
  Сбой любого компонента останавливает второй. Остановка выполняется в обратном
  порядке. Наблюдатель метрик отменяется и завершается перед очисткой процессов;
  переходы HTTP с локального адреса метрик запрещены.
- Каждый процесс помещается в отдельный Job Object с завершением при закрытии.
  Весь графический клиент от администратора не запускается.

## Проверки

Автоматические проверки работают с подставными процессами, каналами и потоками
в памяти. Нативные `sing-box check` и `xray run -test` проверяют схемы конфигураций,
не запускают TUN и не изменяют маршруты. Переключения Happ и реального VPN
агентом не выполнялись.

Проверены режимы all/only/except с постоянной защитой и без неё, HTTPS DNS и
пользовательский DNS, перенос параметров VLESS, ошибки обоих этапов запуска,
отмена и EOF, завершение каждого компонента, порядок очистки, общий срок
ожидания готовности, ограниченные повторные подключения и запрет перенаправлений
метрик. Таблица TCP/PID проверяется на синтетических байтах без вызова сетевого
API Windows. SOCKS-аутентификация проверяется через `net.Pipe` без сокетов ОС.

Работа реального Windows-туннеля, браузера, Discord, утечки DNS/IPv6 и восстановление
после сетевого перехода этой сборкой ещё не подтверждены. Статус «подключено»
означает готовность обоих движков и системного TUN, а не успешный запрос к сайту.
Upstream sing-tun при реальном запуске `auto_route` также временно управляет
WeakHostSend других интерфейсов. Включённый forwarding физического интерфейса
может мешать привязке исходящего транспорта; автоматически менять forwarding
VIORA не пытается. В изолированных проверках эти функции не запускались.

## Происхождение компонентов

Xray и helper собираются Go 1.27.3. Официальный sing-box 1.14.4 собран upstream
Go 1.26.10 и поставляется без изменения бинарника. Происхождение, закреплённые
хеши, ссылка на исходники и лицензия приведены в
`third_party/sing-box/PROVENANCE.md`. В установщик включены GPL-лицензия и архив
исходников sing-box. Обновление компонентов из приложения не выполняется.

Локальный `govulncheck` недоступен; свежая проверка нового бинарника по базе
уязвимостей не проведена. Успешные тесты и проверка хешей не доказывают полного
отсутствия уязвимостей.
