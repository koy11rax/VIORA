# Windows 1.0.4: исправления для повторной проверки

Пользователь установил сборку-кандидат и повторно подтвердил отсутствие
передачи данных. Эта версия не исправила весь пользовательский сбой.
Последующие настольные изменения описаны в `windows-connectivity-1.0.5.md`.
Happ и сетевые настройки при подготовке сборки агентом не менялись.

## Исправленная условная остановка HTTPS

Настольный TUN передаёт в маршрутизатор уже известный IP назначения.
Sniffing с `routeOnly` дополнительно передаёт имя TLS/SNI для доменных правил.
Если ни одно правило не совпало, `IPIfNonMatch` повторно разрешал это имя
через DNS до отправки трафика в тот же стандартный proxy. Медленный резолвер
таким образом задерживал соединение к уже известному адресу.

В `desktop/tunnel/config.go` добавлено последнее правило TCP/UDP → proxy
для режимов «все» и «кроме выбранных». Оно находится после правил DNS,
блокировки IPv6, пользовательских доменов/подсетей и приложений. В режиме
«только выбранные» сохранены прежние выбранные приложения → proxy и
остальные → direct. Постоянная защита по-прежнему заменяет direct на block.

Подсети проверяются по фактическому адресу назначения TUN; доменные правила
по-прежнему используют распознанное имя. Повторное разрешение SNI для выбора
другого IP больше не требуется. Для будущего входа с доменным назначением
(например, SOCKS) это правило нужно оценить отдельно.

В полностью изолированной проверке настоящий gVisor/TUN, dispatcher,
маршрутизатор и TLS работают через потоки в памяти. До исправления сочетание
SNI и медленного DNS воспроизводит таймаут TLS; без SNI тот же запрос проходит.
С последним правилом запрос с SNI проходит с обычной проверкой сертификата и
без лишнего DNS-запроса. Это доказательство устранения конкретного дефекта,
а не доказательство причины всех наблюдавшихся отказов на ПК.

## Другие исправления

- WebSocket использует срок контекста рукопожатия при TCP/uTLS и закрывает
  соединение после неудачного TLS. Проверка сертификата/имени сохранена.
  Overlay и воспроизводимые автономные тесты: `patches/xray-desktop` и
  `tests/xray-websocket`.
- В последующей исходной правке TLS sniffer ожидает оставшуюся часть уже распознанной записи ClientHello,
  не теряя имя SNI после двух частичных чтений. Прежний предел ожидания
  dispatcher и проверка сертификатов сохранены. В первоначальный установщик
  1.0.4, выданный пользователю, эта дополнительная правка ещё не входила.
- TCP-замер во время активного VPN больше не выдаёт локальное подтверждение
  TUN за задержку удалённого сервера. Ожидающий замер также отбрасывается при
  переходе состояния подключения. Ранее наблюдавшиеся 6 мс не доказывали
  доступность VPN-сервера.
- Диагностика различает попытку соединения, завершение WebSocket и передачу
  назначения; предупреждение с именем пакета `common/errors` больше не
  считается ошибкой само по себе. Допускаются только фиксированные категории
  и девять числовых Winsock-кодов. Исходные строки, адреса и секреты не
  сохраняются.
- Исправления установки из 1.0.3 r3 сохранены, включая настоящую версию
  Wintun `0.14.1.0` и проверяемый запуск службы.

## Сравнение прежних сборок

Изучены сохранённые исходники 0.8.1, 0.8.2 и 1.0.0, история Git и старые
Windows-комплекты. Описанное сочетание `routeOnly`/`IPIfNonMatch` уже было в
0.8.1; оно не добавлено последним аудитом. Wintun в проверенных версиях
одинаков. Для исторически работавшей 0.6.5 точного исходного состояния helper
не найдено, поэтому восстановление её поведения побайтно не заявляется.

## Проверки и ограничения

- Helper: 123 успешных именованных проверок, 1 пропущенная проверка установленной
  службы; `go vet` без замечаний. Служба/туннель в тестах не запускались.
- Linux: тестовый файл helper скомпилирован, не запускался.
- Flutter: ранее пройден полный набор 185 проверок, 5 opt-in проверок снимков
  пропущены; после последней правки состояния пройдены 36 целевых проверок,
  анализатор чистый. Эти числа не складываются: наборы пересекаются.
- Windows UI и native компоненты собраны в Release. Новая APK не собиралась
  и телефон не обновлялся.
- MSI: сверены все 30 файлов, версии и защищённые пути компонентов, условия
  обновления и проверяемого запуска службы. Вложенный в EXE пакет совпадает
  с проверенным MSI. Установка и запуск службы не выполнялись.
